# 新版控制台流程

新版网站将旧控制台拆分为独立页面。登录后可通过左侧导航进入各项功能，页面地址也可以直接收藏。

## 推荐使用顺序

1. 在 [概览](https://www.fastapi.cool/dashboard/overview) 检查账户余额、密钥和近期使用情况。
2. 在 [模型广场](https://www.fastapi.cool/pricing) 确认模型名称、能力、支持协议和价格。
3. 如需补充余额或购买套餐，进入 [钱包](https://www.fastapi.cool/wallet)。
4. 在 [API 密钥](https://www.fastapi.cool/keys) 创建调用凭证，并按需选择固定分组或 Auto 分组，以及限制额度、有效期、模型和 IP。
5. 在 [游乐场](https://www.fastapi.cool/playground) 完成站内测试，或按 [API 调用](/guide/api) 配置 SDK。
6. 请求完成后到 [使用日志](https://www.fastapi.cool/usage-logs/common) 或 [任务日志](https://www.fastapi.cool/usage-logs/task) 核对结果。

## API 密钥的新操作方式

创建密钥时，基础设置包括名称、分组、有效期、数量和额度。高级设置可以限制模型与 IP/CIDR。

如果管理员启用了 **Auto 分组**，密钥可以按优先顺序尝试多个可用分组：

- 选择“继承全局 Auto”时，密钥始终使用管理员维护的最新分组顺序；
- 选择自定义顺序时，可为当前密钥单独添加、删除和排序分组；
- 开启“跨组重试”后，当前分组内的渠道不可用时，系统会继续尝试顺序中的下一个分组；
- 实际命中的分组和最终扣费请以使用日志为准。

创建完成后：

- 点击密钥行旁的复制按钮，可复制完整密钥；
- 点击脱敏显示的密钥，可按需查看完整内容；
- 可随时编辑、停用或删除密钥；
- 密钥泄露时应立即停用或删除，再创建新密钥。

## 钱包与计费

钱包页将余额、充值、订阅、兑换码、邀请奖励和账单记录集中在同一页面。具体显示内容取决于管理员启用的支付与套餐功能。

系统会在进入支付前检查充值数量及充值后的钱包额度；无法安全入账的数量会被直接拒绝，不会继续创建支付。支付回调会在事务中完成订单状态与额度更新，重复回调不会重复增加余额。

最终扣费以 [使用日志](https://www.fastapi.cool/usage-logs/common) 中记录的模型、输入输出用量、分组倍率和其他计费项为准。

## 使用日志的新信息

新版使用日志会更明确地区分普通请求与流式请求，并记录流式响应是否正常完成。日志详情会显示请求记录到的 reasoning effort；使用动态计费规则时，「条件乘数」会标出本次实际命中的条件和倍率。消费金额旁出现工具图标时，表示本次请求包含 Web Search、File Search、图片生成等工具调用附加费；打开日志详情可以查看更完整的计费信息。

分组、密钥名称和用户名筛选框仍是普通文本筛选，但隐藏状态改为页面内遮罩，并关闭浏览器自动填充，避免密码管理器把凭据误填进日志条件。需要核对筛选值时可正常切换显示状态。

游乐场的流式文本会对新到达的普通文字做短暂淡入；行内代码、代码块和已完成内容不会重复动画。编辑历史消息时，如果内容尚未保存，取消编辑或离开页面都会先提示确认，避免误丢修改。

任务日志现在会为插件任务显示统一的任务详情、计费用量事实和可用产物。视频、图片或其他产物通过与具体任务及产物键绑定的访问地址打开；普通用户不会看到渠道密钥、上游任务 ID 等私有信息，管理员与超级管理员看到的诊断字段也按角色分层。

## 从旧地址迁移

旧控制台链接仍可能被自动重定向，但建议更新书签和客户端说明：

| 旧入口 | 新入口 |
| --- | --- |
| `/console` | `/dashboard/overview` |
| `/console/token` | `/keys` |
| `/console/log` | `/usage-logs/common` |
| `/console/task` | `/usage-logs/task` |
| `/console/topup` | `/wallet` |

管理员功能已分别移动到「渠道」「模型」「用户」「订阅」「系统信息」和「系统设置」页面，普通用户不会看到这些入口。

## 管理员渠道与兑换码操作

异步图片、视频等任务平台已迁移到沙箱 JavaScript 插件。超级管理员可在「任务插件」页面查看出厂插件、从市场安装插件或上传自定义插件；同名自定义版本会覆盖出厂版本，停用或删除覆盖版本后恢复出厂版本。关闭总开关会同时停止出厂与自定义插件，并影响仍在途的任务，请先核对页面列出的渠道数与在途任务数。

创建任务插件渠道时必须选择已注册插件并填写 Base URL；具备 `task_plugin.bind` 权限的管理员才能绑定。插件声明的模型、公开路由、OpenAI Responses / Video 协议能力和计费用量字段会共同决定可用接口与定价编辑器；插件冲突或公开路由冲突不会被市场安装强制覆盖。系统设置中的「任务公开地址」用于生成任务产物地址，未配置时才回退到服务器地址。

管理员在「渠道」中抓取上游模型后，新增模型与已有模型会按厂商分组展示，便于搜索、批量选择和核对；Qwen 的 TTS 模型会归入 Qwen 分类。保存前仍应检查模型名称和映射，无法识别的名称会显示在 `Other` 分组。

渠道连通性测试会按所选协议发送请求：Claude 和 Gemini 使用各自的原生请求格式，Gemini 流式测试使用 `:streamGenerateContent` 路径。因此测试成功表示该渠道的对应原生协议入口可用，不代表同一模型自动支持其他协议。

在「系统设置 → 模型与渠道 → 路由可靠性」中，定时渠道测试支持三种范围：检查除手动禁用外的全部渠道、只检查已开启自动禁用的渠道、或只复查等待恢复的自动禁用渠道。后两种模式可减少对健康渠道的不必要探测；是否在测试成功后重新启用渠道仍由对应开关控制。管理员还可把测试并发设置为 1–32；任务会按该上限并行执行，同时保留进度统计和取消能力。

Advanced Custom 渠道现在提供可视化路由编辑器，可从全部协议、仅 OpenAI、仅 Claude 或仅 Gemini 模板开始，再按实际需要保留路由。每条转发路由可分别配置入口路径、上游路径、协议转换、认证方式和精确模型范围；同一路径可按模型拆分，但只能保留一个最终兜底路由。模型列表与余额查询属于独立的管理路由，替换转发模板时会保留；余额响应若不是 OpenAI `credit_summary` 格式，只显示原始上游 JSON，不会错误更新渠道余额。

OpenAI、Anthropic、Codex、Advanced Custom、Sub2API 和 New API 等兼容或网关渠道会按协议显示「字段透传控制」。只启用上游确实支持的字段；例如 `service_tier`、`inference_geo`、`speed`、`store` 或 obfuscation 控制在不同协议中的支持范围并不相同。参数覆盖规则还可以读取 `user_id`、`user_group`、`token_group` 和实际命中的 `using_group`，用于按用户或分组调整上游参数。

配置自定义 OAuth 提供商时，「访问策略」可以直接填充「等级且已激活」或「组织或角色」模板，并支持嵌套的 `and` / `or` 条件。拒绝提示可使用 `provider`、`field`、`op`、`required`、`current` 及 `current.roles` 等变量；访问策略留空表示不额外限制用户。

管理员在用户绑定管理中可以解绑邮箱、GitHub、Discord、微信、OIDC、Telegram 和 LinuxDO 等内置登录方式。服务端设置 `PASSWORD_LOGIN_ENCRYPTION_ENABLED=true` 后，登录页会先读取临时公钥并加密密码字段再提交；该能力默认关闭，关闭时继续使用原有登录请求格式。

编辑兑换码时，页面会先加载服务器上的最新记录；加载完成前不能提交。若只修改名称或有效期而没有改动额度，系统会保留原始内部额度，避免因显示货币换算和小数精度造成额度变化。额度输入步长会随当前货币或 Token 显示设置调整。

个人资料中的访问令牌不会回显现有值，重新生成前必须确认。生成后的新令牌只显示一次，关闭窗口后即从页面清除，同时旧令牌会立即失效；请先安全保存新值，再立即更新仍使用旧令牌的客户端。该操作还受关键接口限流约束，不要连续重复生成。
