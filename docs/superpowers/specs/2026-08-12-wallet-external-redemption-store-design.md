# 钱包外部兑换码购买入口设计

## 背景

钱包中的支付宝仍需保留，但该渠道目前受到限制，不应继续作为主要购买途径。需要为用户提供一个醒目的链动小铺入口，让用户购买兑换码后，通过钱包现有的兑换流程增加额度。

系统已经具备可配置的 `TopUpLink` 选项。后端在充值信息接口中通过 `topup_link` 返回该配置，钱包也已经将其作为 `topupLink` 传给 `RechargeFormCard`。复用这个选项可以避免新增支付渠道、订单模型、支付回调或接口。

## 选定方案

将现有的 `TopUpLink` 系统配置设置为：

`https://pay.ldxp.cn/shop/fastapi`

当 `topupLink` 非空时，在钱包的“付款方式”区域中，将外部购码入口显示在标准付款方式按钮之前：

- 主文案：`链动小铺购码（推荐）`
- 辅助文案：`支付后在下方兑换`
- 使用 `target="_blank"` 和 `rel="noopener noreferrer"` 在新标签页安全打开配置的链接。
- 保留下方兑换码输入框后的现有购码链接，不作删除或替换。
- 保留支付宝及其他所有已配置的付款方式，并排列在该入口之后。

这个入口仅负责安全跳转到外部网站。订单、支付和兑换码交付均由链动小铺负责；New API 不会为这条路径创建订单、接收支付回调或自动增加额度。购买完成后，用户返回钱包并在现有兑换码输入框中兑换额度。

## 界面与数据流

1. 数据库中的 `TopUpLink` 配置加载到应用的选项映射中。
2. `/api/user/topup/info` 将其作为 `topup_link` 返回。
3. 钱包将 `topup_link` 作为 `topupLink` 传给 `RechargeFormCard`。
4. `RechargeFormCard` 先显示外部购码入口，再显示支付宝及其他已配置的付款方式。
5. 用户点击入口后，链动小铺在新标签页中打开，钱包页面继续保留，方便用户购买后兑换。

如果第三方网站不可用，钱包及现有付款方式仍能正常使用。如果 `TopUpLink` 为空，则不显示新的外部入口。

## 修改范围

实现范围有意限制为：

- 修改一个钱包组件。
- 添加新入口所需的多语言文案。
- 增加一个聚焦的组件测试，验证排列顺序、链接地址、安全的新标签页行为、提示文案，以及下方原有链接仍然保留。
- 将生产环境已有的 `TopUpLink` 配置设置为用户提供的链接。

无需修改支付后端、数据库结构、付款方式配置格式、支付回调路由或文档站部署工作流。

## 验证方案

- 先添加聚焦测试，并确认测试因缺少外部入口而失败。
- 完成使测试通过所需的最小组件修改。
- 运行聚焦测试、钱包及前端测试、类型检查、涉及文件的代码检查、格式检查和前端生产构建。
- 推送 `my-custom`，等待现有部署工作流完成，并验证线上钱包在支付宝之前显示外部入口，且链接行为符合预期。
